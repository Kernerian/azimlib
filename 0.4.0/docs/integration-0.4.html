0.4 development integration and delivery gates

This is an unreleased source-tree preview, not an installed PyPI 0.4 release. Candidate metadata is 0.4.0; published stable files remain 0.3.0. The authoritative 112-item checklist records completed work and pending evidence; successful local examples do not approve a release.

Reproduce the cumulative gallery

From a reviewed source checkout, install only the required extras explicitly:

python -m pip install '.[gui,qt,gpu,dev]'
python -I tools/validate_integration_040.py --gpu --native --output integration-review
python -I tools/check_release_progress_040.py

Use a new output directory for every run. The validator checks the source import, shared azimlib/azimlib.pyplot state, original geocoding-to-route scene, topology clipping, geocentric roundtrip, urban shadows, Earth–Moon composition, solar globe and lit volume. It exports PNG/SVG/PDF according to capabilities, records source, example and export SHA-256s, and writes an HTML comparison index. GPU is explicit: an unavailable context fails rather than silently falling back. Native review captures only the application's verified windows. They do not grant human approval.

For an isolated wheel installation, pass --installed. For the dependency-free core, use --installed --core without GPU/native flags. Core produces vector SVG/PDF where supported and PDF volumes; raster export requires a provider. Small core images test packaging and capabilities, not typography at display size.

CI and release separation

The existing 28-job CI contract is preserved. The manual integration-0.4.yml workflow prepares 22 additional jobs: 15 core OS/Python combinations, three native capture jobs, three optional-provider absence jobs and one explicitly software Mesa GPU job. Software Mesa is not hardware-GPU evidence. This workflow has read-only repository permissions and no publication steps. Its configuration/tests do not constitute a successful hosted execution.

Before release, run complete exact-candidate CI, the applicable native review, final 14.01/14.06 revalidation and same-commit distribution audits. Four original IDs are explicitly deferred, not passed: rescope. Current stage-14 preparation distinguishes local evidence from exact hosted CI, human review and final distributions. The scoped publication checker rejects every unchecked active ID; four named deferments are preserved. Unknown series, arbitrary unchecked-ID bypasses and failed functional checks remain rejected.

See migration, draft release notes, the static original gallery, benchmark methodology and third-party boundaries. Raw external references, private paths, logs and local development environments are excluded from packages.

Unpublished preparation and publication gate

Stage-14 tooling distinguishes --purpose prepare from the default publication gate. Preparation permits only 14.04/14.05/14.07/14.08 to remain open; it is not publication approval. Publication requires all 108 active IDs complete, exactly the four named deferments still unchecked, and no other unchecked ID. Human 14.05 and explicit final 14.08 acceptance cannot be inferred from CI.

For explicitly headless Linux Mesa validation, select --gpu --gpu-context egl (and an installed EGL driver). Desktop default context selection is unchanged; the validator does not silently consume a GPU-context environment variable.
